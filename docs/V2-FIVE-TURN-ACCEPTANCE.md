# ShiCiJP V2 — 5 轮优化与验收计划

制定日期：2026-10-24。项目：https://shicijp.com/；竞品：https://rakuyomi.net/。
执行原则：**首屏即核心、先质量后扩量、公开页面可抓取、所有改动必须可回归**。轮数为用户对话轮次，当前方案算第 1 轮。

## 已确认的现状（轮 1）

- `public/` 是生产网站根目录，GitHub Pages 由 `.github/workflows/pages.yml` 在 main 推送触发部署。
- 现有文本分词、浏览器内查词、汉字详情、JLPT 筛选、认识词本地记忆、导出 Excel/CSV/Anki/TXT、Excel 连续朗读；不可在重构时丢失。
- `package.json` 已定义 `test`、`test:jlpt-db`、`test:jlpt-content`、`audit:jlpt-coverage`。
- `scripts/audit_jlpt_coverage.py` 明确将中文内容标为 `draft_editorial_review`，覆盖率≠人工审校。
- 词汇来源及 JLPT 级别为非官方参考；不得称其为 JLPT 官方指定词表。
- Rakuyomi 提供独立词汇、语法、阅读、测试页面；本项目应先补 N5 内容入口和学习闭环，而不是一次复制全部功能。

## 不可妥协的验收门槛

### A. 原功能不可退步
1. 分词：粘贴、示例、文件上传可用；原文中点击词能找到词条。
2. JLPT 等级筛选、振假名显示、排序、认识词记录和恢复功能正确。
3. 导出 Excel、CSV、Anki、TXT 均有真实数据和正确格式。
4. 汉字详情及 Excel 朗读工作；纯浏览器本地处理原则不变。
5. Windows Chrome + 移动端 390px 与 320px 宽度无水平溢出，关键输入/按钮无需大幅滚动。

### B. N5 内容
1. 以 `data-src/n5.csv` 去重词条作为参考集合；禁止凭空宣称官方清单或发布已审校百分比。
2. 每个发布词条必须有日语表记、读音、非空中文义项、日语例句及中文例句译文；格式审查为程序必过项。
3. 中文内容若仍为草稿，应在编辑元数据和前台适当位置明确“待审核”；不允许用“100%人工校对”。
4. 统计 distinct 参考键、别名匹配、重复项、缺失项并留档；已有 `npm run audit:jlpt-coverage` 是基准。
5. 语义抽样不少于 60 条：优先歧义词、助词、量词、多义词、汉字同形异义、含别名词；人工核校不能被自动非空检查替代。未完成须明示。

### C. SEO
1. N5 总览、分类、详情页必须是正常 HTTP 200 静态可访问 URL，HTML 源码直接含正文主体、唯一 H1、title、description、canonical。
2. 网站首页到 N5 分类最多 2 次点击；词条从相应分类 1 次点击到达；分类之间有返回与导航。
3. 同一个词条仅有一个规范 URL；链接必须编码正确，避免重名 slug 冲突，重复内容不得大规模索引。
4. sitemap 中仅含 canonical 的、可索引的 200 页面；robots 不得误拦截页面；不发布大规模“空词典页”。
5. 若有结构化数据，内容必须与页面一致；不得伪造评分、点评、官方 JLPT 权威等信息。
6. 搜索结果排名、GSC 收录量、真实流量作为上线后观察指标，**不是可以在 5 轮内保证的指标**。

### D. 交互与性能
1. 首页打开即可使用文本框，阅读/词库入口次于分析器；无营销长文压过操作区。
2. 搜索与词条点击、认识/不认识状态、复习切换均有键盘支持与清晰反馈。
3. 所有重要按钮在触屏上可用；文本不被遮挡，深浅主题可读。
4. 保持本地分析，无需后端账户；若添加存储需注明使用范围。
5. 不虚报 Core Web Vitals；使用 Lighthouse 真机/模拟数据实测后附结果。

## 回归命令（从仓库根目录执行）

```bash
npm ci
npm test
npm run test:jlpt-db
npm run test:jlpt-content
npm run audit:jlpt-coverage
npm run serve
# 另一个终端：
BASE=http://localhost:8000/ node scripts/e2e_test.js
```

以上是验收指令，不代表已经运行通过。新页面需增加生成一致性与 SEO 检查，并记录 CI 执行状态。
